Custodia · security summary

For the reviewer deciding whether this runs on your network.

Every statement below is checkable against the source, which ships with the tool. Where the honest answer is “no” or “not yet”, it says so.

What it is

A program that reads records and saved reports out of a system you are retiring and writes them to a single SQLite file with a signed completeness certificate. It runs inside your environment. It is not a service, is not hosted, and has no cloud component.

Network behaviour

Outbound connections — three, and only three.

  1. The source system you point it at. Your database, your report server, or your Salesforce org. This connection is the product’s entire purpose.
  2. A timestamp authority, only if you switch it on. RFC 3161 timestamping is off by default. When enabled it sends a SHA-256 hash and nothing else — no record content, no metadata, no identifiers. The authority learns that a hash was timestamped, never what it covers.
  3. Nothing else. No telemetry, no analytics, no licence check, no update check. There is no code path that contacts Collatio Labs.

Inbound connections: none. The operator console binds to 127.0.0.1 only and is not reachable from the network. The verifier your organization keeps makes no network calls at all — which is why it still works in 2036.

Access it requires

  • One read-only database account. Custodia never writes to a source. A stored report definition containing INSERT, UPDATE, DELETE or DROP is refused before execution rather than run.
  • No administrator rights. No agent installed. No schema changes. No writes to any source system.

What it writes

One SQLite file in a directory you choose, plus the verifier and a README beside it. Nothing else is created anywhere.

Credentials and keys

Source credentials are supplied per run and held in memory only — never written to disk, never written into the archive, never echoed into a web page. Ed25519 signing keys live outside the archive at file mode 0600, so a distributed archive never carries the key that signed it.

Cryptography

Ed25519 signatures and SHA-256 hashing via the audited cryptography library — not hand-rolled — with an RFC 6962 Merkle tree covering every record. None of it is configurable: one curve, one hash, no options to get wrong.

The archive is signed, not encrypted, and that is deliberate. An encrypted archive whose key is lost is a destroyed archive, and the guarantee is that this opens decades from now with free tools and no vendor. Confidentiality belongs to your storage layer, where you already hold the keys. What Custodia guarantees is that no record can be altered, inserted or removed without verification failing.

How to check any of this yourself

  • Read the source. It ships with the tool and is not obfuscated.
  • Run it with network monitoring on and confirm the only egress is your own system.
  • Run the verifier on an air-gapped machine. It completes successfully.
  • Alter one byte in an archived record and re-verify. It fails.

Limitations, stated plainly

  • Custodia scans the source you point it at. It does not discover systems on your network and does not claim to.
  • Collatio Labs holds no SOC 2, FedRAMP or ISO 27001 certification. The software hosts nothing and retains no customer data, so the auditable scope is minimal — but the certifications do not exist and we will not imply otherwise.
  • General and excess liability insurance are in force. Professional liability and cyber coverage are bound prior to contract execution.
