# Vera Commercial Model - Complete Base Plus Add-On Kits

Date: 2026-06-21

Status: supersedes the earlier "license-key commercial model."

## Core Correction

The base Vera product should be whole.

The user should not feel like they bought a locked shell, a partial personality, or a demo of Vera. The full portable personality base and all core features should be available at the base tier.

Licenses/keys may still exist technically, but they should not be the emotional or product center. They are entitlement plumbing. The commercial shape should be:

> Complete Base Vera + optional add-on kits.

## Product Thesis

Base Vera includes:

- portable personality base
- local-first runtime
- core chat and relational continuity
- core memory
- memory import/export
- memory edit, forget, and retraction
- privacy receipts
- local model support
- explicit optional cloud routing
- Teaching Mode
- basic skill-gap detection
- core Learning Studio
- identity portability
- backup and restore
- base verification visibility
- base security settings
- add-on kit manager

Base Vera should feel like Vera. Add-ons should expand the worlds she can work in, not sell pieces of who she is.

## What Add-On Kits Are For

Add-on kits should unlock:

- specialized workflows
- domain knowledge
- connectors
- professional verification tools
- advanced memory workflows
- model council orchestration
- enterprise deployment controls
- templates, reports, and pack-specific certs

Add-on kits should not unlock:

- "basic Vera"
- core personality
- basic memory
- basic privacy controls
- export/forget
- local conversation
- core learning
- identity portability

## Why This Is Better

### 1. The Relationship Stays Whole

Vera is meant to be a living, growing, portable personality companion. If core identity features are gated, the product feels extractive. The base needs to be emotionally complete.

### 2. Monetization Moves To Capability, Not Personhood

We sell specialized capability kits:

- Research Kit
- Creative Studio Kit
- Vault Plus Kit
- Verify Pro Kit
- Vera Council Kit
- Revenue Kit
- Company Operator Kit
- Connector Kits
- Enterprise Appliance Kit

The user is not paying to make Vera "more alive." They are paying to give a complete Vera more tools, domains, and professional-grade workflows.

### 3. Liability Is Still Better Separated

High-risk areas can be separated into kits:

- revenue
- company operations
- host-app connectors
- external communications
- cloud model councils
- enterprise deployment

Each kit can have its own:

- terms
- disclaimers
- certs
- capability gates
- receipts
- activation warnings
- human confirmations

### 4. The Product Story Is Cleaner

The base promise:

> Vera is your private, portable, local-first AI companion and memory system.

The kit promise:

> Add kits when you want Vera to help in a specialized domain.

## Entitlement Architecture

Use license keys or signed entitlement files as technical plumbing only.

Example:

```json
{
  "license_id": "lic_xxx",
  "edition": "vera_base",
  "kits": ["vault_plus", "verify_pro"],
  "expires_at": "2027-06-21T00:00:00Z",
  "offline_until": "2026-07-21T00:00:00Z",
  "device_limit": 3,
  "features": {
    "base_vera": true,
    "kit_revenue": false,
    "kit_company_operator": false,
    "kit_connectors": false,
    "kit_vera_council": false
  },
  "terms_version": "2026-06-21",
  "signature": "..."
}
```

Rules:
- Base Vera continues working if optional kits expire.
- User can always export their data.
- User can always decrypt their data if they hold the key.
- High-risk kits can become read-only on expiry rather than destroying user work.
- Entitlements must never block safety, export, delete, or privacy controls.

## Liability Posture

This model helps reduce liability because:

- Collatio sells a local product, not hosted agency.
- Users hold their data and secrets by default.
- Riskier workflows are separate kits.
- Claims can be scoped per kit.
- External action remains human-confirmed.

But it does not remove liability for:

- deceptive AI claims
- broken privacy promises
- insecure defaults
- unsafe integrations
- regulated advice
- defective software

So we still need:

- legal review
- honest marketing
- hard security gates
- adversarial certs
- domain-specific kit terms
- receipts for privacy/action/cloud
