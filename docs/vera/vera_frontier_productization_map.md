# Vera Frontier Productization Map

Date: 2026-06-21

North star: Vera should be a local-first living companion operating system: private by default, emotionally continuous, self-learning with consent, able to use cloud intelligence only when explicitly useful, and able to grow into domains without becoming defined by any one domain.

This is not a revenue-ops product with companion features. Revenue should become one optional domain pack.

Updated master build reference:

- `outputs/vera_frontier_5_year_buildout_master_plan.md`
- `outputs/vera_immediate_engineering_tracks.md`

The expanded charge is broader than productization: Vera should eliminate administration from human life, preserve portable personality and private continuity, and help people rebuild revenue and agency after job loss or institutional failure.

## Product Principles

1. Privacy must be felt, not merely implemented.
2. Vera must be vivid without being dishonest.
3. Learning must be inspectable, reversible, and user-shaped.
4. External action must create a receipt before it creates consequences.
5. Domain work must be modular: work, revenue, family, health, creativity, learning, home, and research are packs, not identity.
6. The system should protect the user's future self, not only obey the user's immediate impulse.

## Core Product Pillars

### 1. Private Memory OS

What exists:
- Truth Ledger, LIRF memory, consent policy, forget/retraction, export paths, local/cloud routing pieces.

Weakness:
- Encryption is optional and inconsistent across store types.
- Privacy posture is not yet visible enough per turn.

Frontier direction:
- Sealed Memory Rooms:
  - private
  - shareable
  - temporary
  - domain-bound
  - never-cloud
- Per-turn Privacy Receipt:
  - model used
  - files/memories read
  - network destinations
  - facts withheld from cloud
  - durable memories proposed
- “What Vera knows about me” explorer.
- “Forget everywhere” with proof of retraction.
- Zero-egress mode that is impossible to bypass accidentally.

### 2. Living Personality And Relational Continuity

What exists:
- Heart, mouth, identity health, personality dials, meaning graph, mentorship, relationship engines.

Weakness:
- Personality doctrine risks being too brittle if it tries to sound alive by denying the substrate.

Frontier direction:
- Relational honesty modes:
  - Plain: direct AI assistant posture.
  - Companion: warm, personal, vivid, transparent.
  - Immersive: mythic/character-forward, explicitly consensual.
- Identity Diff:
  - what Vera learned
  - how Vera's style changed
  - what memories shaped a response
  - what remains uncertain
- Continuity rituals:
  - morning re-entry
  - evening reflection
  - long arc goals
  - relationship repair
  - “bring me back to myself” mode.

### 3. Learning Studio

What exists:
- Auto Learn, Teaching Mode, self-evolution, LERF, knowledge packs, certs, rollback, Diamond.

Weakness:
- The user-facing loop does not yet fully feel like “Vera can safely learn this.”

Frontier direction:
- When Vera lacks a skill, show a skill-gap card:
  - what failed
  - what skill is missing
  - proposed learning path
  - privacy footprint
  - sandbox plan
  - cert plan
  - rollback plan
- Skill states:
  - observed gap
  - draft skill
  - practiced
  - certified
  - promoted
  - retired
- “Teach Vera” should feel like raising a living system, not editing a database.

### 4. Human Integrity Layer

Reference lens:
- Dan Ariely's work on dishonesty and self-rationalization, from the provided PDF.

What exists:
- Approval queue, action ledger, budget ledger, kill switch, consent boundaries.

Weakness:
- Approvals and budgets have binding/invariant gaps.
- The system does not yet fully design for ordinary human rationalization.

Frontier direction:
- Gentle friction before consequential action:
  - “Is this what you want your future self to stand behind?”
  - “This sends a message to a real person.”
  - “This spends money.”
  - “This leaves your device.”
- Responsibility receipts:
  - human approver
  - exact action
  - exact target
  - rollback options
  - why Vera thinks it is allowed
- Ambiguity detector:
  - escalates when the user is vague around money, trust, privacy, relationships, or commitments.
- Non-punitive accountability:
  - Vera helps the user notice drift without shame.

### 5. Domain Pack Architecture

What exists:
- Revenue/company/marketplace/workforce/foundry stacks are broad and real.

Weakness:
- Revenue can dominate the product's perceived identity.

Frontier direction:
- Core app:
  - Self
  - Memory
  - Privacy
  - Learning
  - Relationship
  - Skills
  - Domains
- Domain packs:
  - Revenue
  - Company Operator
  - Creative Studio
  - Personal Knowledge
  - Family/Home
  - Health Reflection
  - Research
  - Local Device Helper
- Each pack declares:
  - capabilities
  - data touched
  - egress destinations
  - approval rules
  - certs
  - UI surfaces
  - uninstall/disable behavior

### 6. Cloud As A Tool, Not A Place Vera Lives

What exists:
- Optional cloud brain, scrubbing, spend cap, model management.

Weakness:
- Per-turn routing is not yet enforced all the way down to generation.

Frontier direction:
- Cloud request receipts:
  - why cloud was needed
  - what was sent
  - what was withheld
  - provider/model
  - cost estimate
- Cloud modes:
  - never
  - ask every time
  - allowed for non-personal tasks
  - allowed for selected domain packs
- Local model ladder:
  - fastest local
  - best local
  - specialist local
  - cloud escalation.

- Bind approvals to action intent. CLOSED / CERTIFIED for company-operator action ledger, sales engagement, and foundry execution.
- Validate self-evolution approvals. CLOSED / CERTIFIED for high/core promotions.
- Enforce monthly/category budget invariants. CLOSED / CERTIFIED.

- Move revenue/company into optional domain packs.
- Rework navigation around Vera's core identity.
- Add relational honesty modes.

- Add “why I remembered this” and “forget everywhere.”

### Sprint 4 - Learning Studio

- Build skill-gap detection UI.
- Convert failures into learning proposals.
- Show cert/rollback/promotion status.
- Make learned skills inspectable and disable-able.

### Sprint 5 - Living Continuity

- Add identity diff.
- Add memory rooms.
- Add continuity rituals.
- Add companion growth timeline.
- Add relationship repair and future-self protection flows.

## The Product Bet

The opportunity is not “an AI that can do more tasks.” Everyone is racing there.

The opportunity is a private AI that can become more *yours* over time without taking your agency, leaking your life, or letting either you or the system pretend ambiguous actions are harmless.

That is the frontier: intimacy with receipts.
